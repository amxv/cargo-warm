## Source of truth

Distribution configuration lives in `dist-workspace.toml`. The GitHub Actions release workflow is generated output:

```bash
dist plan
dist generate
```

Do not hand-edit `.github/workflows/release.yml`. Change `dist-workspace.toml` and regenerate it.

## Default targets

The template builds:

- Apple Silicon macOS
- Intel macOS
- ARM64 Linux
- x64 Linux
- x64 Windows

## Installers

The same release graph generates:

- shell installer for macOS/Linux
- PowerShell installer for Windows
- npm binary package
- GitHub Release archives/checksums
- GitHub artifact attestations

There is no custom Node downloader in the repository. The npm package is generated by `dist` during release.

## npm publishing

The generated npm publish job expects a GitHub Actions secret named `NPM_TOKEN`.

The package name is configured by `npm-scope` and `npm-package` in `dist-workspace.toml`. Bootstrap keeps those values synchronized with the generated project identity.

## Tagging

The Cargo package version and Git tag must agree. After updating the version and changelog:

```bash
just check
just docs-check
just docs-build
dist plan
just release-tag 0.2.0
```

`release-tag` verifies Cargo metadata before creating `v0.2.0`.
