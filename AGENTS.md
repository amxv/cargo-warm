# AGENTS.md

Guidance for coding agents working on `cargo-warm`.

## Purpose

`cargo-warm` reduces first-build latency in new Rust worktrees without making separate checkouts share writable Cargo state.

The central invariant is:

```text
share immutable/COW filesystem blocks
+ keep mutable Cargo/rustc state private per worktree
+ let Cargo/rustc validate freshness
```

Do not trade this invariant away for a faster benchmark.

## Architecture

- `src/main.rs`: process exit/error boundary only.
- `src/lib.rs`: argument normalization and command dispatch.
- `src/cli.rs`: `clap` command model.
- `src/commands/`: user-facing command implementations.
- `src/cache.rs`: Cargo path discovery, compatibility checks, cloning, registry, and worktree helpers.
- `tests/`: binary-level behavior.
- `Cargo.toml`: package metadata, dependencies, and Rust lints.
- `dist-workspace.toml`: release/install targets.
- `docs/`: independent Astro/ZueDocs workspace.
- `.github/workflows/release.yml`: generated by `dist`; do not hand-edit it.

## Commands

Fast edit loop:

```bash
just check-fast
```

Full Rust validation:

```bash
just check
```

Useful focused commands:

```bash
cargo fmt --all -- --check
cargo check --locked
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

Docs, run serially:

```bash
just docs-check
just docs-build
```

Release configuration:

```bash
dist plan
dist generate
```

## Correctness and safety

- Never point two active worktrees at one writable Cargo build directory.
- Never treat a copied cache as proof that outputs are correct. Cargo and rustc own validation.
- Never silently fall back from COW/reflink to a huge physical copy.
- Refuse to seed from or into a workspace that is actively compiling.
- Toolchain or configuration uncertainty should reduce reuse, not weaken correctness.
- `gc` must only delete state the tool can prove it owns.
- Tests must isolate `HOME`/`XDG_CACHE_HOME` when exercising registry behavior. Never touch a developer's real cargo-warm registry.

## Performance work

The north-star scenario is:

```text
warm main checkout
-> create nearby worktree
-> seed private compiler/build state
-> first cargo check feels close to a warm check
```

Measure the whole path, including seed time and physical disk growth. Separate dependency reuse from workspace-local crate reuse. When a seeded build recompiles, use Cargo fingerprint diagnostics before inventing a fix.

## Coding conventions

- Rust 2024 with the pinned toolchain in `rust-toolchain.toml`.
- Keep `main.rs` tiny and keep command behavior testable through library modules.
- Prefer typed `clap` arguments.
- `unsafe_code` is forbidden; `dbg!`, `todo!`, and `unimplemented!` are denied.
- Keep `Cargo.lock` committed.
- Keep new source files below 1,000 LOC.

## Release boundary

`dist-workspace.toml` is the source of truth for supported binary/install targets. `.github/workflows/release.yml` is generated output. If distribution changes, edit the config, run `dist generate`, and commit both.

For a release request, follow `.agents/skills/release/SKILL.md`.
